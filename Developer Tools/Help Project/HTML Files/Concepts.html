Introduction

VI Helpeks is the toolkit designed to build comprehensive HTML/CHM help for LabVIEW VIs and Function Palettes. It generates help files on the basis of information taken from the source files. As well, it allows to customise content of the generated help files individually or on group basis.

VI Helpeks generates help as a set of HTML files. You might use these HTML files directly for documenting your VIs or compile them into a Compiled HTML Help (CHM) file (click here for details on creating compiled help).

Build Rules

VI Helpeks generates help files using Build Rules defined for source files and file groups. A Build Rule is a set of parameters that describes how to build help file, its content and location.

VI Helpeks project has hierarchical structure and consists of project items. Every project item has its own Build Rule. Any rule parameter can be set to a specific value, or be defined as Default. If a perameter is defined as Default, its actual value is obtained using inheritance scheme described below.

Project items

There are three basic types of project items:

1) Master Rule defines main project properties and default rule for building help files. The Master Rule is represented in the Project Tree as Project Files item, which contains source files and groups.

2) Group contains source files and other groups, and defines default rule for items it contains. A Group inherits rule parameters from its parent group, if any, or the Master Rule.

3) File is a source file for which the output HTML file is to be built. It's possible to define individual rule for every file in the project. If any parameter in the file rule is defined as Default, it is inherited from either the parent group, if any, or the Master Rule. A file rule is only applied to the file it is defined.

File membership and rule inheritance

A project might contain a file as static or/and dynamic instance. A file is Static if it's added to the project explicitly. A file is Dynamic if it's added automatically because another project file refers to it (e.g. Palette menu or Polymorphic VI). A project can contain only one static instance of a file or/and several dynamic instances of it.

A file has only one build rule, independently of how many instances of it exist in the project. If a project contains several instances of a file, the actual build rule for the file is obtained the following way: If there is a static instance, actual rule parameters are inherited from its parent group. Otherwise, rule parameters are inherited from a parent group of the instance that has minimal indent level in its parent group.

Source files

Source files are files that present in the Project Tree. Any files referred in an item's build rule are not considered as source files. A source file can be either a LabVIEW file (e.g. VI or Palette menu) or any other file. Description of how VI Helpeks operates on different source file types is present below.

Source LabVIEW files

VI Helpeks generates help for the following LabVIEW file types:

  • ordinary VI
  • template VI
  • polymorphic VI
  • Palette menu

VI Helpeks creates several output files for a source file. Output files are HTML files, Image files, CSS and JS files. HTML and Image files are generated automatically. CSS and JS files are taken from the file rule, listed in Source CSS and JS Files category. Location of output files is defined in the file rule, Target Paths category.

NOTE: Help files are not generated for LabVIEW file types other than listed above.

Source HTML files

VI Helpeks copies source file to location defined for HTML files in the file rule, Target Paths category.

VI Helpeks might perform some converion of HTML file content:

  • Replace references to project source files with hypertext links to respective output files (see details below)
  • Replace product information keywords (PINF) with values defined in the Product Information category of the project. For this, put a keyword with the "%%VIHKWD_" prefix into HTML file. For example, %%VIHKWD_%PINF_COPYRIGHT% is replaced with copyright notice defined in a project. You can find complete list of the product information keywords in the Context Help for controls of the Product Information category.
  • Insert links to CSS files defined in the file rule into position in HTML file where the following tag found:
    <!-- #INSERT:STYLESHEETREFS : -->
  • Insert links to JavaScript files defined in the file rule into position in HTML file where the following tag found:
    <!-- #INSERT:JAVASCRIPTREFS : -->
NOTE: VI Helpeks doesn't automatically copy any files referred in a source HTML file, you should either explicitely include such files to the project and specify proper location for them or manually copy the files.

Source Image, CSS and JS files

A source file is merely copied to location defined in the file rule, Target Paths category. A relevant target path from the category is used for image, CSS and JS files.

Other Source files

A source file is merely copied to location defined in the file rule, Target Paths category. A path for HTML files is used.

Linking between help files

VI Helpeks automatically generates hypertext links between output help files for Palette menus and VIs referred in them. It doesn't create links between help files for VIs and non-LabVIEW files automatically.

In order to create a hypertext link in an output help file to another output help file, you should use a Reference to desired source file, which is a link in the special format:

<a href="hprj:source_file_name">name to appear</a>
or
<a href="hprj:source_file_name#anchor">name to appear</a>

, where source_file_name is a name of source file in your project to which you want to create link.
 

This Reference can be used in any Description parameter for VI, Palette, Control or Control Value defined in a file rule. As well, you can place such Reference into a source HTML file if you need create hypertext link to help file for a project file.

TIP: Activate a shortcut menu for a file in the Project Tree and select option Copy to Clipboard >> Reference to the file to create a proper reference and put it to the Clipboard.
TIP: Use Insert Reference button on the right of any Description control of a file rule in order to select a desired source file and insert reference to it into edit position in the description.
TIP: Use shortcut menu for a Description control to insert reference to a project file, web site or e-mail address into edit position in the description.

VI Terminals and Control Rules

If you need define custom parameters for generating help for a VI terminal control or indicator, create a Control Rule for it. A Control Rule is part of a project item rule, it can be defined for a VI, file group or the Master Rule. An item rule might have multiple Control Rules.

TIP: Define control rules in the Control Descriptions category.

VI Helpeks identifies controls using the Control Identifier which is a string combined from a control label and labels of its parent controls (for cluster members). Control Rule has to be defined for every desired control (top level or a member of parent control). A cluster member does not inherit rule parameters from its parent cluster.

TIP: You can easy create Control Rules using Import button on the right of Control List. As well, in VI Terminals dialog, you can copy desired VI controls to the Clipboard and paste them to the Control List with the Paste button on the right of it.

If you define a Control Rule for a VI, the rule is applied to the VI's control or indicator that satisfies the Control Identifier specified in the rule. If you define a Control Rule for a file group or the Master Rule, the control rule is applied to relevant controls for all VIs in the group (following the rule inheritance scheme described above).

NOTE: VI Helpeks might have trouble of control identification if a VI have terminal controls and/or indicators with non unique names (labels).

Enumerated values

VI Helpeks includes list of values for controls and indicators of Enum and Ring types to output help files by default. By using a Control Rule you can add description for enumerated values is to be added to help file.

TIP: When you create a Control Rule by doing import or pasting to the Control List, list of enumerated values is automatically created for controls of an enumerated type.

When VI Helpeks generates help for an enumerated control or indicator, it lists actual values retrieved from the control or indicator. A value list defined in the Control Rule is only used to find description for every value; herewith, the search is going in the Strings property of Enum controls, and Values property of Ring controls.

Template Files

VI Helpeks generates help files on the basis of HTML template files. It uses individual HTML template file for every source file type (ordinary VI, polymorphic VI and Palette menu). An HTML template file might use CSS and JS files for defining its style and behavior; such CSS and JS files become a part of the template therefore. A set of HTML template, CSS and JS files used in a project determines appearnce and behavior of the output help files.

VI Helpeks comes with two sets of template files. When you create a new project, the Master Rule is configured to use template files relevant for the project type you choose: Default or JavaScript based. If your choise is Default, template files for generating pure frameless HTML files are used in the Master Rule. The JavaScript based selection makes the Master Rule use template files for generating help that utilize JavaScripts for providing additional features similar to LabVIEW Help.

VI Helpeks provides possibility to use custom template files. For example, you might want to change style, layout or content of your help files; VI Helpeks gives you this opportunity (with some restrictions however). For this, create your own template files taking for the basis template files comming with VI Helpeks. Then, in the Source Template File category, define template files are to be used. As typically, you can do it for the whole project (Master Rule), groups or individual source files. Similar situation is for CSS and JavaScript files except you should define them in Source CSS & JS Files category.
