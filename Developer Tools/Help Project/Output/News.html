VI Helpeks UI (Project Manager)

  • Erasing a template file path control causes it to reset to the default value.
  • The Compiled HTML Help dialog now warns the user on an attempt to create an HHP project that already exists.
  • Project File (.hgprj) stores the target .CHM file path as relative to the path of the .HHP file.
  • Bug Fix: In the Control Descriptions category, changing selection in the Controls List while editing properties of a Control, could cause improper value assignment. This has been resolved.

Help Generation

  • The Help Info File is now always created, regardless of whether .HHP or .CHM files are being generated.
  • Default Template files used for help generation (HTML/CSS/JS) are updated to ensure high-quality documentation.
  • Custom HTML Templates can use new keywords to define the appearance of VI Name. The default %%VIName%% can be replaced with %%VIShortName%% or %%VIFullName%%.

VI Helpeks API

  • API VIs are updated and optimized.
  • API example VI is updated for better understanding and learning.
  • API example VI can now be opened directly from the LabVIEW menu via Tools >> VI Helpeks >> Help and Support.

Miscellaneous Changes

  • Various minor enhancements, code cleanups, and performance tweaks were implemented throughout the VIs, which are not explicitly listed in this file.

News and changes in version 3.0

 

  • Free and Open: As of version 3.0, VI Helpeks has transitioned to Free/Source-Available software. VI Helpeks VIs now feature unlocked Block Diagrams, allowing you to view, modify, and adapt the toolkit to your specific workflow.
  • JavaScript: VI Helpeks now utilizes new native JavaScript files to embed into generated HTML/CHM help. This eliminates third-party dependencies and strengthens the security profile for both the toolkit itself and the help files it produces.
  • HTML and CSS: Updated HTML templates and CSS files, combined with new JavaScript files, enable the creation of high-quality HTML/CHM help.
  • File Association: VI Helpeks no longer automatically sets Windows file associations for its project files. This strengthens the security profile of the toolkit. Please use the File menu to open projects. (This behavior can still be enabled manually; see the Migration from Previous Versions topic below.)
  • General: Includes various code optimizations and UI enhancements.

Migration from Previous Versions

  • Default JS Files: When opening a project created in a previous version, VI Helpeks will automatically update references from old JavaScript files to the new native ones. This transition is designed to be seamless and should not affect help file functionality if default CSS and HTML templates are used. However, we recommend a quick verification of your generated output after the update.
  • Custom CSS files: If your project uses custom CSS, you should update it with the code from either the 'default.css' or 'default2.css' file, depending on your project type (Default or JS based). These files are located in the <labview>\project\VI Helpeks\_Template folder. Copy the code marked with the comment "new VI Helpeks 3.0 definitions" from the default CSS into your custom file.
  • Custom HTML Templates: If your project uses custom HTML templates, it is recommended to update the <body> tag. Replace it with the <body class="helpVI">, <body class="helpPolyVI">, or <body class="helpMenu">, depending on the template's intended use (ordinary VI, polymorphic VI, or palette).
  • File Association: To preserve VI Helpeks project file associations, use the support and example files located in the <labview>\project\VI Helpeks\_rsrc folder to build the VI Helpeks Project Runner executable. This allows you to restore file associations manually (via Windows Settings or the VI Helpeks Settings dialog) without modifying the core toolkit's security profile.

 

 

News and changes in version 2.0

Project File Association

In Windows, VI Helpeks creates file type association for its project files. This means you can open VI Helpeks project from Windows Explorer or any other program which uses file type association for opening a document; for example, LabVIEW Project Explorer.

NOTE: This feature is activated automatically during VI Helpeks installation if both VIPM and LabVIEW are running with administrator privilege. To activate the feature manually, start LabVIEW with the "Run as administrator" option and open VI Helpeks. Perform the project file type association in the VI Helpeks Settings dialog.

VI Helpeks API

API VIs are intended to build help project programmatically and assist a developer in creating help system for his/her VIs.

TIP: API VIs can be found in the Addons >> VI Hepleks API function palette.

Help generation

  • Palette files that have the "Synchronize with directory" option are supported now.
  • Resolved the conflict of non-unique HTML file names when there are source files with the identical names (e.g. VIs with the same name might belong to different project libraries or classes, or palette files might have identical name in different folders, etc.).
  • Resolved issue of searching hotspot regions on VI connectors image for VI terminals that have caption.
  • A source HTML file might contain Product Information Keywords with the "%%VIHKWD_" prefix. During building help, the keywords are replaced with values defined in the project. Complete list of the keywords can be found in the Context Help for controls of the Product Information category in VI Helpeks GUI.
  • A build log file indicates additional information on the build status.
  • more minor improvements in help generation...

VI Helpeks GUI

  • It's possible to define custom path of the target CHM file now. Configurable in the Compiled HTML Help dialog.
  • Build help can automatically create CHM file after generating HTML files. The option is configurable in the Compiled HTML Help dialog.
  • It's possible to open CHM file from the main window now. It's also possible to open the topic in CHM file for a desired source file (use shortcut menu for desired file in the project tree).
  • New menu option for editing source files. For non-VIs, it opens a source file in an editor program. Program association is configurable in the VI Helpeks Settings dialog.
  • New VI Documentaion utility assists in editing VI documentation properties.
  • Many utility dialogs are improved.
  • Main GUI menu is modified.
  • more minor GUI improvements...

VI Documentation utility

The VI Documentation utility assists in documenting your VIs. It provides an easy way to define the description and relevant properties of a VI, as well as its controls and indicators.

TIP: To edit properties of a VI, use Tools >> VI Helpeks >> VI Documentation menu of the VI.

 

 

News and changes in version 1.1

Product Information category

New Product Information Category contains parameters describing the product for which the help files be generated, as well as author, copyright, contact and other relevant information. The parameters define values for Product Information Keywords that can be used for generating help files.

In addition, the Product Information category defines whether help files contain Product Information Section and its content.

Help generation

Any text obtained from Palettes and VIs is now properly encoded to HTML format if it contains reserved HTML characters. There is an exception for <B> tag in Palette, VI or Control description that is passed to output files. There is no exception for VI and Control names, value strings, etc.

Shortcut menus

Shortcut menus are now available for Description controls. Along with typical edit options, the menus provide options to insert HTML formatting tags, reference to project files, links to web sites and e-mail addresses, and Product Information Keywords.

Main menu

New option to clean up build folder in the Build menu.

Miscellaneous

  • VI Helpeks launcher indicates progress of starting program.
  • Improved Quick Tips dialog.
  • Updated examples.
